# 阶段唤醒模板

这个模板用于 `xman-flow` 在进入某个阶段前，显式唤醒对应阶段 skill。

## 使用要求

按 `.ai-configs/conventions.md`〈阶段职责与证据复用〉确定当前阶段仍需解决的问题；已有成果足以回答时记录复用，不重复启动。确需调用时，读取对应 `SKILL.md`，带入下面的输入，按完整协议执行后返回主流程。

## 阶段映射表

| 阶段 | 默认 skill | `metadata.outputs.type` |
|---|---|---|
| explore | brainstorm | brainstorm |
| analyze | req-analyze | analysis |
| specify | prd | prd |
| design | design | design |
| plan | create-plan | plan |
| implement | code-by-plan | progress |
| validate | harness | harness |
| review | review | review |

输出路径由 `.ai-configs/conventions.md` 按 skill 声明的类型解析，继承当前需求的 task-id。`reflect` 是收尾复盘，对应 lessons 类型；完成声明检查按 `harness`〈选择验证范围〉中的「只核对完成声明」执行，需要留档时用 verification 类型。两者都不另设主流程阶段。

说明：

- 选中独立 `validate` 阶段时由 `harness` 执行；短流程的相关检查可附着在 implement 内，独立阶段省略时按主流程记录原因
- 完成声明检查按公共证据规则核对，检查记录沿用当前产物
- `review` 分「需求」和「缺陷与规范」两条线，做法见 review 的 `SKILL.md`；每条发现带证据分级，类比不进结论
- `reflect` 是用户要求时才做的收尾复盘
- `tdd-guard` 通过注入机制叠加到 implement 阶段，不是独立阶段

## 通用唤醒模板

```text
[阶段唤醒开始]
阶段：<explore | analyze | specify | design | plan | implement | validate | review>
默认 skill：<mapped-skill>
输入：
- 待解决问题：<本阶段独有、尚未解决的问题>
- 用户需求：<需求原文或摘要>
- 已授权范围与已确认决定：<目标、范围和用户保留的确认点>
- 已确认结论与产物或记录条目：<上一阶段产物及相关决策的位置>
- 可复用证据：<已有检查记录及覆盖范围>
- 本阶段独有产出：<新增判断或内容；文件交付写产物类型和路径>
- 输出所有者与负责内容：<最终写入者、当前执行者负责的文件或章节>
共享产物按 `./shared-artifact.md`处理。
完成后返回：结论与依据、产物或章节稿、实际补验与复用结果、已确认部分与未决事项、风险及下一动作。
[阶段唤醒结束]
```

## 子代理版本模板

如果当前阶段需要交给子代理执行，派发 prompt 前必须显式包含以下内容：

```text
开工前先用 Read 工具读取当前仓库中的以下文件，并按完整协议执行：
- 当前阶段 skill：`../../../skills/<mapped-skill>/SKILL.md`
- 如果不知道仓库根目录，先用 Glob 搜索 `**/skills/<mapped-skill>/SKILL.md`

你当前负责的阶段信息如下：
- 阶段：<stage>
- 待解决问题：<本阶段独有、尚未解决的问题>
- 用户需求：<需求摘要>
- 已授权范围与已确认决定：<目标、范围和用户保留的确认点>
- 已确认结论与产物或记录条目：<上一阶段产物及相关决策的位置>
- 可复用证据：<已有检查记录及覆盖范围>
- 本阶段独有产出：<新增判断或内容；文件交付写产物类型和路径>
- 输出所有者与负责内容：<最终写入者、当前执行者负责的文件或章节>

执行要求：
- 按对应 skill 的完整协议完成当前阶段
- 已授权步骤直接执行；局部可逆细节依据代码与验证决定，业务或契约未决选择返回主流程
- 不要越过当前阶段直接处理下一阶段
- 按 conventions 的阶段证据规则和共享产物写入责任执行
- 完成后只返回：结论、根本原因或关键依据、产物路径、验证结果、风险与下一动作。使用实际名称，不使用编号标志位或字母方案
```

## 自检清单

进入下一阶段前，核对本阶段问题是否已回答、证据是否覆盖当前对象、输出是否由指定所有者写入；逻辑完成和记录完成分别核对。建议及假设不自动变成已确认，下游只依赖已确认部分；只要求单阶段时在该范围结束。下一动作由主流程决定。
