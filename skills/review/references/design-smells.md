# 用结构异味提出可验证的问题

这些名称用于提醒审查者继续查证，不是十二条强制编码规则。先按项目标准、契约和当前任务判断；项目明确采用的结构，不因名称落入此表就要求重写。工具已覆盖的格式与静态检查无需重复报告。

只有查到具体位置、触发条件和实际后果，候选才进入 review 问题清单。严重程度来自后果；仅凭「像某种异味」不能阻止合并。以下修法均为可选方向，采用前要证明它能减少当前问题，也要核对兼容性与验证成本。

## 名称含混 · Mysterious Name

- **线索**：名称无法区分对象、单位或动作，调用方需要反复读实现才能使用。
- **查证后果**：找实际调用或失败测试，核对是否把分当元、把查询当写入、把瞬时状态当最终状态；单纯不喜欢命名不算问题。
- **可选处理**：把真实含义写进名称或类型。外部协议名、团队通用缩写已有清楚定义时保留；若始终无法准确命名，先查职责是否混杂。

## 重复代码 · Duplicated Code

- **线索**：同一业务规则在多个位置以相同结构出现。
- **查证后果**：对照输入、规则来源和变更记录，确认是否已有一处改了另一处漏改，或同一输入得到不同结果。
- **可选处理**：把确实共同变化的规则放到共享函数或模块。外形相似但业务约束不同的代码，不急于合并；生成代码也不应手工抽取。

## 过度依赖别人的数据 · Feature Envy

- **线索**：一段方法频繁拆开另一对象的数据，自己拼出它的业务判断。
- **查证后果**：检查是否绕过数据所有者的不变量，以及该对象改字段时有多少调用点必须跟着改。
- **可选处理**：把判断移到拥有规则的模块，或提供表达业务意图的查询。只读报表、跨对象聚合有其职责，不因访问字段多就迁移。

## 总是一起出现的数据 · Data Clumps

- **线索**：一组字段反复共同传递、校验或修改。
- **查证后果**：找漏传、顺序传错、字段不一致的真实路径，确认这些值是否属于同一概念、是否必须一起有效。
- **可选处理**：用参数对象或领域值类型表达这组约束。只碰巧一起出现、允许独立变化的字段不强行绑定。

## 用基本类型承载复杂含义 · Primitive Obsession

- **线索**：字符串、数字或布尔值承载金额、单位、状态等规则，校验散落在调用方。
- **查证后果**：验证不同单位、非法状态组合或未校验值能否进入业务计算，确认已有上游校验是否兜住。
- **可选处理**：在合适入口构造有校验的值对象、枚举或标记类型。单纯传输数据、已有可靠校验且无混用成本时，基本类型可以足够。

## 重复的分支选择 · Repeated Switches

- **线索**：同一种类或状态在多处触发相似的 switch / if 链。
- **查证后果**：沿新增一种类别的改动查漏项；核对各分支究竟共享行为，还是不同业务问题恰好用了同一字段。
- **可选处理**：集中共同选择逻辑、使用查找表，或在确有行为差异时引入多态。一个短分支或用途不同的分支无需统一。

## 一次修改散落多处 · Shotgun Surgery

- **线索**：修改一条规则，需要同步改许多互不相邻的文件。
- **查证后果**：用实际提交和调用链说明哪些位置必须一起变化，以及漏一处会让哪条业务路径不一致；文件数量本身不是证据。
- **可选处理**：把共同变化的决策收拢到一个模块或契约。跨层协议升级必然涉及多层时，应先改善契约和验证，不能只追求少改文件。

## 一个模块被不同原因反复改动 · Divergent Change

- **线索**：同一模块同时因互不相关的业务规则、外部协议或存储策略而修改。
- **查证后果**：比较几次具体改动，找耦合造成的回归、共同发布负担或测试准备成本，排除只是同一个文件的不同独立函数。
- **可选处理**：按变化原因划分职责，让各自约束在局部成立。小而稳定的模块不必为了目录整齐拆分。

## 为假想需求建立抽象 · Speculative Generality

- **线索**：新增扩展点、参数或通用框架，但当前调用方没有使用这些变化能力。
- **查证后果**：核对规格、兼容要求和真实调用，量出它增加的必传配置、分支、测试或排障成本；尚未启用不等于没有已确认需求。
- **可选处理**：在没有现实约束时收回多余选项、内联薄抽象。公开兼容层、已批准的迁移窗口需要单独保留证据。

## 调用方穿过一长串对象 · Message Chains

- **线索**：调用方沿对象内部结构连续导航，知道了超出任务所需的中间层。
- **查证后果**：检查一个内部结构调整是否迫使多个调用方修改，以及空值或错误是否被推给每个调用方重复处理。
- **可选处理**：由合适的模块提供直接表达意图的操作。流式构造器、查询 DSL 的链式 API 可能正是公开契约，不能按点号数量定罪。

## 只做转发的中间层 · Middle Man

- **线索**：一层几乎逐个转发同名操作，理解功能时必须额外跳转。
- **查证后果**：做只读的 deletion test：设想去掉它，权限、兼容、错误归一或测试替换职责会不会散到调用方；追出它实际承担的工作。
- **可选处理**：没有独立职责时可内联转发或直接依赖实际目标。门面、适配器与安全边界即使代码短，也可能有明确价值。

## 继承后拒绝遵守父契约 · Refused Bequest

- **线索**：子类或实现类禁用、忽略继承的大部分操作，调用方需要识别具体类型才能使用。
- **查证后果**：按父契约的合法调用做测试，确认替换实现后是否失败或产生不同副作用；文档允许的可选能力不算违约。
- **可选处理**：缩小接口、按能力拆分契约，或用组合表达共享实现。保留兼容性要求，避免仅为去掉继承引入更多调用方分支。

## 来源与改写边界

十二项选择来自 Matt Pocock 的 [code-review](https://github.com/mattpocock/skills/blob/c55ee46073ed923f86ce59a5eb3b6d895095d1b7/skills/engineering/code-review/SKILL.md) 中选用的 Fowler 异味清单；该项目采用 [MIT 许可](https://github.com/mattpocock/skills/blob/c55ee46073ed923f86ce59a5eb3b6d895095d1b7/LICENSE)。这里用中文重新说明验证路径、后果和反例，沿用本仓的证据与排序规则，不导入上游的固定双代理流程。

Fowler 本人也说明，异味是值得继续调查的迹象，并不自动证明设计有错：[Code Smell](https://martinfowler.com/bliki/CodeSmell.html)。
