# 按计划实施方法补充

仅在计划跨模块、存在迁移或执行中发生偏离时读取。步骤、偏离处理和输出以 `SKILL.md` 为准，这里只补它没写的做法。

## 跨模块修改的顺序

先改事实源和公共契约，再改调用方。工程约束按 skill 安装目录里的 `create-plan/references/engineering-checks.md` 把适用条款落实到行为和验证。注释解释「为什么」，不复述代码「做什么」。

## 发现计划错误

先写清这四项，再决定是记录后继续还是按边界问题处理：

```text
发现 → 对成功标准的影响 → 最小调整 → 新的验证方式
```

## 发生错误

不要只在报错位置加保护。沿输入、调用链、状态写入和输出找到最早分叉点；根本原因未确认时先设计最小实验。

错误记录只保留现象、根本原因、最终处理和回归验证。失败尝试只有会防止重复踩坑时才保留。

## 验证到业务完成

命令成功不等于业务完成。按实际范围验证入口、权限、状态变化、失败反馈、数据持久化、异步处理和最终结果，先验证当前任务，再验证受影响模块和真实用户路径。
