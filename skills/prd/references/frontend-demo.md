# PRD 前端改动 demo

PRD 落档后，凡是需求改变了现有页面上用户能看到或能操作的内容，就生成一份 demo：照抄现有页面的样式，叠加 PRD 里的改动，配一份说明。评审的人打开 demo 就能看到“改完长什么样、怎么点”，不必在脑子里把文字还原成界面。只要页面上有用户可见的变化，包括数值或含义变化、提示与帮助文案、筛选项或导出内容，就生成 demo；只有页面上看不出任何变化的纯后端需求才不生成，并在 PRD 完成概括里说明原因。

## 定位现有页面

先找到 PRD 涉及的每个页面在源码里的位置，再动手画。

- 从路由或菜单配置找到页面组件，再找它用到的组件库、主题变量和全局样式。

每个页面记下：入口（菜单路径或路由）、页面组件文件、主要子组件、主题或样式来源。找不到源码或设计规范时，在说明里写明缺口和样式依据（截图、线上页面或相近页面），不凭印象编造样式。

## 照抄样式

- 布局、栅格、间距、字号、颜色、圆角、阴影、图标风格和文案语气都取自源码和主题变量，不用新的视觉风格。
- 只画 PRD 涉及的页面和区域；页面的其余部分保留骨架和真实的区块标题，能看出改动在原页面中的位置即可。
- 组件外观照组件库默认样式还原（表格、按钮、标签、弹窗、抽屉、表单、分页、空状态），不引入外部 UI 库。
- 展示数据贴近真实业务（企业名、税种、期间、金额、状态），在页面上标明“示例数据”。

## 叠加改动

- 改动区域加可开关的标记（例如细边框加“新增”“调整”角标），顶部提供“显示改动标记”开关，关掉后就是上线后的样子。
- 每个标记都能对应到 PRD 里的一条范围或规则，叫法和 PRD 保持一致。
- 被移除或替换的内容，在说明里写清楚原来是什么。

## 简单交互

PRD 里写到的用户操作都做成能点的交互，用原生 JavaScript 实现，不连真实接口：

- 按钮、标签页切换、筛选、展开收起、弹窗、抽屉、二次确认。
- 状态变化：操作后行内状态、标签和可用按钮按 PRD 的状态规则切换。
- 失败与边界：至少演示一个权限不足或业务失败的反馈，以及空状态；有角色差异时提供角色切换，按 PRD 的权限显示或隐藏操作。
- 加载和异步结果用短延时模拟，并给出 PRD 规定的提示文案。

交互不需要覆盖所有分支；没做的分支在说明里列出。

## 产物

- **demo**：单个 HTML 文件，CSS 和 JS 全部内联，离线可打开，不引用任何外部资源。按 `.ai-configs/conventions.md` 的产物路径约定保存为可点击原型。
- **说明**：与 demo 同目录、同主名的 `.md`，主名后加 `-说明`。包含：
  1. 一句话：这个 demo 演示了什么改动。
  2. 页面清单：每个页面的入口、参照的源码文件和样式来源。
  3. 改动清单：改了什么 → 对应 PRD 的哪条范围或规则 → 在 demo 里怎么看到。
  4. 交互清单：怎么点、会看到什么、对应哪条验收标准。
  5. 与真实实现的差异：示例数据、模拟接口、未做的分支、样式依据缺口。
- 在 PRD 的「依据」后补一行 demo 和说明的路径。

## 自检

用浏览器打开 demo（可调用 Skill 工具，参数为 `webapp-testing`）：页面无控制台报错，每个交互都能触发并出现预期结果，关掉改动标记后版面不错位，和源码页面并排对比时布局与配色一致。发现不一致就改 demo，不在说明里掩盖。
