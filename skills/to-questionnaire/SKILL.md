# 异步澄清问卷

把用户需要补齐的信息，转成收件人能独立理解和回答的短问卷。它适合准备给他人的澄清材料；当前用户自己能做出的产品取舍，仍按正常需求讨论处理。

## 先确定问谁、拿回答案后做什么

1. 读取用户已给的背景、材料和已确认结论，提取收件人的角色、掌握的信息，以及这次需要回收的事实或决定。已有信息直接使用，不再让用户复述。
2. 只向用户补问影响问卷对象或范围的缺口，例如收件人负责什么、答复将用于哪项决定。可以把互不依赖的缺口一次问清；不能把应由收件人回答的业务问题反问给本来就不知道答案的用户。
3. 将每项回收需求写成“需要知道的内容 → 用于哪项决定 → 谁能回答”。区分收件人能提供的事实与其有权作出的批准；不了解权限时，不把询问意见写成正式审批。

收件人掌握的信息不足以覆盖全部需求时，按已知职责拆分对象；无法判断谁知情的项目注明待转交。不要为了生成一份看似完整的问卷，要求同一个人猜测其他团队的答案。

## 编写收件人可以直接回答的问题

使用 [问卷模板](assets/templates/questionnaire-template.md)，按任务需要删减，先写最影响决策的问题。

- 开头用一小段话说明用途、收件人与答复如何使用。背景只放回答必需的已知事实；日期、期限和答复渠道只使用用户提供的信息，不代用户承诺。
- 一问只收一个事实或一个决定。将“谁负责、多久完成、出了问题怎么办”拆成独立问题；相关问题可归到同一主题，编号只表示回答顺序。
- 问题与收件人的知识和语言匹配。需要选项时写清选项的实际含义及影响，留出不同做法的回答空间，不能用带倾向的选项诱导确认。
- 已确认的事实放在背景，不再改写成必答题。每题下方留答复位置，允许“不知道”“部分确定”以及必要的适用范围；证据来源可选填，不把每个回答变成举证任务。
- 有依赖的问题写明适用条件，例如“仅当需要外部审批时回答审批时限”；不要让收件人同时回答互斥前提下的整组问题。超出本次决策的问题删除，开放补充题按需保留。

异步问卷可以一次覆盖多项已明确的回收目标。它的阅读顺序和条件分支用于减少来回沟通，不要求收件人逐轮等待代理继续提问。

## 检查覆盖并交付

1. 将用户要求回收的每项事实或决定映射到对应问题的实际标题；标明哪些已由现有材料回答。缺少对应问题就是遗漏，找不到用途的问题应删除。
2. 站在收件人角度检查：是否要猜背景才能答、是否一题包含多件事、是否要求回答其不掌握的知识。再站在用户角度检查：收到答案后还需要自行猜哪项决定；不能用自己推测的答案补齐缺口。
3. 交付问卷及简短的回收映射。用户要求保存时优先使用指定位置；其他落档按 `.ai-configs/conventions.md` 中适用的产物约定处理，不新造目录规则。只要对话文本时，直接给可复制的问卷。

生成问卷不包含发送、发布或联系收件人。用户另行授权发送时，再按指定对象和渠道执行；不要把文档里的“收件人”当成发送授权。

收到答复后，按原回收目标整理“已回答、部分回答、仍缺哪条信息”，保留答复者的不确定性和意见分歧。只追补仍影响决定的缺口，未答和“不知道”均不代表同意。
