# 给 agent 用的工具

Skill 带脚本时，脚本是给 agent 跑的，不是给人跑的。写成给人用的样子，agent 就得靠猜。

**为什么要有脚本**：一件事如果每次都要 agent 现写一段代码去做（点个按钮、核对一遍覆盖、跑一次巡检），
那每次写法都不一样、对不对全看运气，而且那段代码本身要占掉一大块上下文。做成一条命令，
agent 敲一下就有结果——省上下文、结果可复现、脚本本身还能被测试。

六条：

1. **输出机器可读。** 至少给一个 `--json`。对齐的彩色表格是给人看的，agent 得去解析文本，格式一改就崩。
2. **会改东西的命令必须有 `--dry-run`。** 删文件、改软链、写远端、覆盖配置——先让人看一眼要发生什么。
3. **错误信息要说该怎么办**，不只说哪里错了。「缺少 X」不如「缺少 X，跑 `<命令>` 生成」。
4. **`--help` 写全。** 每个子命令都能单独 `--help`，并带一个能直接复制粘贴的例子。
5. **用子命令分层**，别把所有开关摊在一层。`tool spec match <路径>` 好过 `tool --spec --match --path=...`。
6. **一条命令干完一件事。** 别让 agent 为了完成一件事连敲五条命令，再自己把结果拼起来。

新增带 `scripts/` 的 skill 时按这六条自检。现有脚本按需要补，**不要为了齐整一次性重写**。
