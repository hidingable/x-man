# 记一次具体失误

用户当场指出一次失误、要求记下来时读；复盘里有条目通过三问、要写成长期规则时也读。记录写进当前项目的 `.ai-configs/evolution/`：

- `YYYY/MM/*.md`：单次事件，保留现场、根因、纠偏方案和验证证据。
- `patterns/*.md`：长期规则，写「避免什么」和「换成什么」。

字段含义和分类见 `mistake-schema.md`。

## 值得记的

- 用户明确否定了结果：「不行」「不对」「重新做」「没按最优方法」。
- 判断错了：误读需求、误判根因、没验证的假设、记错的 API、语法或版本。
- 选了次优路径：能做成，但成本更高、风险更大或验证更弱。
- 发现了更好的替代技术或做法，旧规则该作废。

纯主观偏好、只剩「下次注意」的感想、临时噪音不记；凭据、密钥、个人隐私和生产敏感数据不写进记录。

## 步骤

1. 先搜有没有同一条教训，有就更新原记录：

   ```bash
   rg -n "关键词1|关键词2" ".ai-configs/evolution"
   ```

2. 确认事实：用户原始要求、失败现象、错误做法、正确的替代做法、验证证据。
3. 新问题建一条事件，每条至少带一个以后默认遵守的规则：

   ```bash
   python3 "<skill 目录>/scripts/new_entry.py" \
     --root "$PWD" \
     --summary "错误摘要" \
     --trigger "用户说不行/测试失败/代码评审指出问题" \
     --category "wrong-method" \
     --symptom "出现了什么现象" \
     --wrong "错误做法或错误判断" \
     --better "更优技术或方法" \
     --guardrail "以后默认遵守的规则"
   ```

4. 同类问题出现过两次以上、来自稳定的反模式，或旧做法已被更好的方案替代时，写进模式规则。新做法推翻旧规则时直接更新原模式文件，让一个问题只有一条现行建议：

   ```bash
   python3 "<skill 目录>/scripts/upsert_pattern.py" \
     --root "$PWD" \
     --pattern "模式名称" \
     --problem "反复出现的问题" \
     --avoid "应该避免的做法" \
     --replace-with "更好的替代技术/方法" \
     --decision-rule "以后如何判断该用哪个方案" \
     --verification "如何验证规则生效"
   ```

5. 回复里写出新增或更新的记录路径。

## 每条记录要写清

- 错误动作：误判了什么、漏看了什么、为什么不该这么做。
- 替代做法：更好的方法是什么，好在哪个维度。
- 验证：怎么证明新做法有效。
- 触发信号：以后看到什么情况要想到这条记录。

事件文件留一次性的细节，模式文件只留长期有效的规则。复盘、progress、review 文档可以当证据来源，模式文件里只摘关键几行。
