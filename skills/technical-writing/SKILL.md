# 开发者文档

大部分难读的技术文档，问题不在文笔，在**一篇文档里塞了四个互相打架的目的**。

## 先定这一篇是哪一种

四种，来自 [Diátaxis](https://diataxis.fr/)。写之前必须选定一种。

| 种类 | 读者是谁 | 他要什么 | 写成什么样 |
|---|---|---|---|
| **教程** Tutorial | 新手，还不懂 | 跟着做出一个能看见的东西 | 一条路走到底，每步都给确切命令和预期结果 |
| **操作指南** How-to | 有经验，有具体问题 | 解决手上这一件事 | 直接给步骤，不解释背景 |
| **参考** Reference | 知道要找什么 | 准确查到某个细节 | 干、全、结构一致，像字典 |
| **说明** Explanation | 想搞懂为什么 | 理解背景和取舍 | 讲清当初考虑过什么、为什么这么选 |

### 混起来会怎样

```
❌ 教程里插一段「关于并发模型的说明」
   → 新手正跟着敲命令，被一段读不懂的原理打断，以为自己漏了什么

❌ 参考里夹一句「我们推荐先创建项目再配置」
   → 来查参数的人得先把建议读完才找到那个字段

❌ 操作指南里从头讲起
   → 他知道自己要干嘛，就想要第三步那行命令
```

**判断办法：写下一段之前问一句「这段服务的是刚才选定的那种读者吗」。** 不是就删掉，
或者拆成另一篇再互相链接。

## 四种各自的硬要求

**教程** —— 唯一目标是让新手成功，不是教全。
- 从零开始，不假设装过什么、配过什么。
- 每一步给能直接复制的命令，和**照做之后应该看到什么**。
- 只走一条路。不写「你也可以用 X」——选择会让新手卡住。
- 不解释原理。想解释就链到说明那篇。
- 结尾要有一个能看见的成果。

**操作指南** —— 读者知道自己要什么。
- 标题写成他会搜的那句话：「怎么把产物落到自定义目录」。
- 第一句写清适用前提，让人快速判断该不该往下读。
- 直接进步骤。
- 分叉写清条件（「用 Docker 的看这条，本地跑的看那条」）。

**参考** —— 准确和完整压倒一切。
- 结构一致：每个条目字段顺序都一样，方便扫。
- 写清类型、默认值、必填与否、取值范围。
- 不推荐、不评价、不讲故事。
- 例子给最小可用的那个，不给花哨的。

**说明** —— 讲清为什么。
- 说清当初的问题是什么。
- **写出考虑过但没选的方案，和没选的原因。** 这是这类文档最值钱的部分。
- 承认已知的缺点。回避缺点的说明文档没人信。
- 不夹操作步骤。

## 先写 README，再写实现

要做一个给别人用的包或工具时，**先把教程写出来**——假装它已经做好了，
把使用者的第一段代码写出来。

写不顺就是接口设计有问题：得先调三个初始化、得记住调用顺序、得自己处理五种错误——
这些在写教程的时候会立刻暴露，比写完实现再发现便宜得多。

这一步和 `architect` 的「先写调用点草图」是同一件事的两个入口。
要定的是类型和签名，用 `architect`；要定的是使用者的完整第一次体验，用这里。

## 去掉 AI 腔

以下几类删掉，文档不会变差，只会变短：

| 毛病 | 例子 | 怎么办 |
|---|---|---|
| 空洞形容词 | 「强大而灵活的配置系统」 | 删。直接说它能配什么 |
| 不落地的承诺 | 「让你的工作流更高效」 | 删。或者换成省了哪一步 |
| 每段都总结 | 「综上所述，我们介绍了……」 | 删。读者刚读完，不用复述 |
| 铺垫开场 | 「在现代软件开发中，……」 | 删。第一句就进正题 |
| 凑数的三段式 | 每个概念都硬凑三个要点 | 有两点写两点 |
| 把难点说成简单 | 「只需简单几步即可」 | 删「简单」。它对读者难不难，不由你定 |
| 通篇被动和名词堆 | 「配置的加载是通过……被完成的」 | 换成人做事：「启动时读 config.yml」 |

**一句话检验**：删掉这句话，读者会少知道一件事吗？不会就删。

## 输出

按 `.ai-configs/conventions.md` 保存，或直接写进项目里该在的位置
（README、`docs/`、代码注释）。

**开头先说清这是四种里的哪一种**，用标题或第一句让读者知道自己来对没有。
篇幅长到要拆时，拆成四种各一篇，互相链接，不要合成一篇长的。

### 表达规则

通用规则见 `.ai-configs/conventions.md`〈表达与命名〉。本 skill 另外要求：

- 命令和代码要能直接复制运行，不用 `<your-value>` 这种占位符——给一个真实的例子值。
- 教程里写清每步之后应该看到什么，别让人猜自己做对没有。
- 不用「简单」「轻松」「只需」形容读者要做的事。

## 完成检查

- 这一篇是四种里的哪一种，从标题或第一句看得出来吗？
- 有没有哪一段服务的是另一种读者？有就删或拆。
- 教程：一个没装过任何东西的人，照着做能不能成功？
- 参考：字段的类型、默认值、必填与否是不是都写了？
- 说明：考虑过但没选的方案写了吗？已知缺点承认了吗？
- 随便挑三句删掉——读者会因此少知道点什么吗？不会的话，这三句本来就该删。
