# 复杂迁移与依赖

公共契约要分批迁移、任务之间依赖交错，或数据迁移和回滚影响排序时读。任务字段、顺序和大小以 `SKILL.md` 为准，这里只补迁移计划特有的写法。

## 排任务前先回答

- 权威数据和规则在哪里，谁负责写入和读取。
- 公共契约是否变化，所有调用方是否已找到。
- 失败、超时、重复执行和恢复怎样处理。
- 是否需要数据迁移、配置变化、灰度或回滚。

答不上来的，先补事实；仍会改变实施结果的，按 `.ai-configs/conventions.md`〈授权、实现判断与验证〉确认。

## 分批兼容迁移

例如公共字段要改名，多个调用方必须分批升级：先让提供方兼容新旧字段并验证旧调用；按实际依赖迁移调用方，每批验证新路径；确认旧调用已清空后再移除兼容。清理任务依赖全部迁移完成，迁移批次不互相假设额外前置。

每批写清能保证哪些行为、怎样判断可以交付，以及失败时怎样恢复。某批必须与其他批合并后才能通过，就把共同的集成验证作为交付条件。若全部调用点可在一次改动中完整更新和验证，直接做原子修改，不为采用这个顺序新增兼容代码。

## 风险写法

每条风险写触发信号、影响和处理方式。涉及数据或部署的，写清回退到哪个状态、怎样确认回退成功。
