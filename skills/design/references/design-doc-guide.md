# 设计方案方法补充

仅在页面层级、交互状态或多角色权限复杂时读取。

## 从问题推导设计

```text
用户阻力 → 根本原因 → 设计原则 → 页面与交互决策 → 验证方式
```

每个设计决策都应能沿这条链回溯。无法回溯的装饰性内容删除。

## 信息结构

先确定入口和用户此刻最需要的信息，再安排次要内容。层级按任务重要性，不按后端数据结构或组件树组织。

## 交互闭环

对每个关键动作写清：

- 前置状态和权限。
- 用户动作。
- 即时反馈。
- 数据是否保存。
- 成功后的状态和下一步。
- 失败、取消、重试和恢复。

## 状态设计

加载、空数据、错误和无权限不是占位图，而是用户仍需继续工作的状态。每个状态都要解释发生了什么，并提供可执行下一步。

## 界面规则

优先复用项目已有组件和视觉约定。只有现有模式无法满足用户任务时才新增模式，并说明原因、兼容方式和验收条件。

## 写作

先给设计结论，再给主流程。表达按 `.ai-configs/conventions.md`〈表达与命名〉执行，只删本次产品交互部分的空章节和需求背景复述。与技术设计共享主产物时只改产品交互部分，保留技术契约和已确认决定。
